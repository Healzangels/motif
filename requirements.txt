# v1.17.0: Apprise — unified notification library spanning Discord,
# Slack, Telegram, Pushover, Gotify, Matrix, email, generic webhooks,
# and 100+ other services. motif embeds Apprise for in-process
# dispatch (URLs configured in /settings → NOTIFICATIONS). Homelab
# users can also point motif at an external Apprise API container
# (caronc/apprise-api) via the `apprise_external_url` setting —
# both sinks can coexist. Apprise ships its own service-specific
# transport handlers so motif doesn't need per-service deps.
# Quarterly review like yt-dlp — apprise ships service updates as
# new services are added and transport URLs evolve.
# v1.18.45: floor bumped 1.7.0 → 1.10.0 (latest stable as of
# 2026-04-26). Three minor releases worth of new service support
# + transport-URL evolution; staying on the floor means motif's
# installed apprise has all the latest service handlers.
# v1.22.24: floor bumped 1.10.0 → 1.11.0 (latest stable as of
# 2026-05-29) on the quarterly review.
# v0.51.245: floor bumped 1.11.0 -> 1.12.0 (latest stable, released
# 2026-07-04) on the quarterly review.
# v0.51.353 (quarterly review 2026-09-27): floor bumped 1.12.0 -> 2.0.0 (released
# 2026-09-26). v2 is a BREAKING release for anyone EMBEDDING apprise, which motif
# does, and this file has no upper bound — so the image was already resolving to it
# before the floor moved. Hence the bump is a verification, not a preference: the
# one call site (notify._send_embedded) was A/B'd against 1.13.1 through a loopback
# sink. NotifyType / NotifyFormat / Apprise().add() truthiness are unchanged, and
# notify() now returns an AppriseResult whose bool() keeps v1's meaning — PARTIAL is
# falsy, so a batch where one URL fails still reports failed. Upstream's advice for
# embedders not ready to move is `apprise >=1.0.0, <2.0.0`; motif does not need it.
apprise>=2.0.0
